The client

A command-line chatbot that starts an MCP server, gives its tools to Claude, and runs whatever tools Claude asks for until Claude has an answer. It's the part a host app like Claude Desktop does for you, in about 250 lines.

Source: mcp/mcp-client-typescript/index.ts

One question, start to finish

1. Connect and list the tools

The client starts the server as a child process (node for a .js file, python3 for .py) and talks to it over stdio. It asks for the tool list once, and reshapes each tool into the format the Claude API expects. MCP's inputSchema becomes Claude's input_schema; nothing else changes.

this.transport = new StdioClientTransport({ command, args: [serverScriptPath] });
await this.mcp.connect(this.transport);

const toolsResult = await this.mcp.listTools();
this.tools = toolsResult.tools.map((tool) => ({
  name: tool.name,
  description: tool.description,
  input_schema: tool.inputSchema,
}));

The client is created with versionNegotiation: { mode: "auto" }. It first tries the 2026-07-28 way (server/discover) and falls back to the older initialize handshake for servers that don't support it. The SDK's own default is the older handshake only.

2. The tool loop

This is the agent loop from the overview, in code. Send the question with the tools. If Claude's reply contains tool_use blocks, run each one on the MCP server, send the results back as tool_result blocks, and ask again. Stop when Claude replies with text only, or after 10 rounds.

for (let turn = 0; turn < MAX_TOOL_TURNS; turn++) {
  const toolUses = response.content.filter((b) => b.type === "tool_use");
  if (toolUses.length === 0) return finalText.join("\n");   // Claude is done

  for (const toolUse of toolUses) {
    const result = await this.mcp.callTool({ name: toolUse.name, arguments: toolUse.input });
    toolResults.push({
      type: "tool_result",
      tool_use_id: toolUse.id,
      content: result.content.filter((b) => b.type === "text").map((b) => b.text).join("\n"),
      is_error: result.isError === true,
    });
  }
  messages.push({ role: "assistant", content: response.content });
  messages.push({ role: "user", content: toolResults });
  response = await this.anthropic.messages.create({ model, max_tokens, messages, tools: this.tools });
}

Where each part of a result goes

FieldGoes toWhy
content (text blocks)Claude, as the tool_resultThe model reads prose. Other block kinds (images, resources) would need converting, because MCP and Claude API block shapes differ.
structuredContentThe appTyped data the code can use directly, already checked against the tool's outputSchema. Here it only counts the alerts.
isErrorClaude, as is_errorLets the model see the tool failed and try something else.

Things to notice

  1. The model never talks to the server. Claude only sees tool names, descriptions and schemas. The client decides to run each call, and could ask the user first.
  2. The tool list is sent with every request. That costs context-window tokens, which is why big hosts load tool definitions on demand. This links to the next agent component, context engineering.
  3. The 10-round cap stops a confused model from looping forever. If it is hit, the client says so instead of running more tools.
